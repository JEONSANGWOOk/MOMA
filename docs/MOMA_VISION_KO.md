# MOMA · ArUco · 판넬 로봇팔 통합

`MOMA_Vision.cmd`를 실행하면 기존 MOMA 프로그램의 **비전 · 판넬 작업** 화면을 열고 D455 인식을 시작합니다. 카메라 영상 읽기만 시작하며 실제 로봇 연결이나 이동은 자동 실행하지 않습니다. 기존 `main.py` 실행에도 같은 화면이 추가되어 있습니다.

왼쪽은 로봇팔·판넬 3D, 오른쪽 **카메라 · ArUco**는 실제 D455 영상입니다. 마커 윤곽과 번호를 영상에 표시하고 ID·딕셔너리·XYZ·기울기·RX/RY/RZ와 두 중심 거리·전후 각도를 아래에 표시합니다. 인식된 마커가 많으면 아래 내용을 스크롤하세요. 영상과 수치가 오래되면 이전 영상을 LIVE로 유지하지 않습니다. 마커가 없으면 0개로 표시하며 실제 측정값을 만들어 넣지 않습니다.

오른쪽 **작업 상세** 탭에서 판넬 참고 이미지와 삽입·회전 또는 SIM/REAL 오차를 봅니다. 내용은 세로 스크롤할 수 있습니다. 왼쪽 MOMA 메뉴의 지도, 미션, ACS, 운영·이벤트 로그 등 기존 기능도 계속 사용합니다. 판넬 상태 변경은 기존 이벤트 로그에도 표시하고 상세 판단은 `.delivery/d455_key_panel`에 저장합니다.

AMR 모드는 MOMA 상단에서, 판넬 FR5 모드는 해당 화면의 **SIM / REAL / SIM+REAL**에서 선택합니다. 두 모드는 독립적입니다. [판넬 모드·실기 보정 설명](D455_KEY_PANEL_TWIN_KO.md)을 참고하세요. SIM에서 카메라로 추종하려면 영상 소스를 **D455 실시간**으로 두고 등록된 두 마커가 보이게 합니다. 실제 마커 없이 시험하려면 **내장 모의 카메라**를 선택한 뒤 작업을 시작합니다.

카메라는 별도 작업 프로세스에서 인식하고 Tk 화면에는 JPEG 미리보기만 전달합니다. 같은 카메라 영상과 인식 좌표를 공유하며 중복 카메라 열기를 잠금으로 차단합니다. 비전 탭을 떠나도 필요한 인식·제어 처리는 유지하고 숨겨진 화면의 영상·3D 다시 그리기는 줄입니다. **카메라 중지**는 이 화면이 시작한 작업 프로세스를 종료합니다. 외부에서 실행한 카메라는 해당 프로그램에서 종료하세요. 환경 오류는 `.delivery/d455_camera_worker.log`에 남습니다. 카메라가 보이지 않으면 RealSense Viewer 등 다른 점유 프로그램을 종료하고 **카메라 시작 / 연결**을 누르세요.

기존 MOMA 팔 연결·요청·미션이 진행 중이면 판넬 FR5 연결을 막습니다. 판넬 FR5를 연결한 동안 기존 팔 제어 연결을 막아 제어 주체가 겹치지 않게 합니다. 실제 판넬 작업은 AMR 주행·수동 조작·미션 종료 및 실제 AMR 최신 정지 상태 확인이 필요합니다. 작업 중 그 조건이 깨지면 중지합니다. MOMA의 정지·취소·일시정지와 Esc는 판넬 작업도 함께 중지합니다. 종료 시 실기 요청·정지 응답이 대기 중이면 창을 유지하므로 상태를 확인한 뒤 다시 닫으세요.

개발자 화면에 통합되어 있으며 기존 사용자 모드의 화면 제한을 유지합니다. 판넬 동작을 기존 Taskchain 단계에서 자동 호출하는 기능은 아직 추가하지 않았습니다. 실제 FR5의 카메라/열쇠 TCP 보정·현장 동작 검증도 별도로 필요합니다.

검증 명령: `py -3 tools/moma_vision_smoke.py --camera`는 실제 카메라 읽기, 기존 지도 화면 전환, 통합 화면 확인만 수행하며 FR5 연결·이동 명령을 보내지 않습니다. 마커 인식 자체 시험은 `.venv-vision\Scripts\python.exe tools/d455_aruco_preview.py --self-test`입니다.
