# 후크 파지 우선 설비 정렬 분석

제어 PC `/home/sdc/ws_sdc/viewer`의 scenario.py, scenario_data.py, camera.py 및 호출 해석용 scenario_utils.py를 2026-11-09 다시 읽었습니다. 실제 세 파일은 로컬 검토용 사본으로 보관하고 SHA256을 `config/door_teaching_reference.json`에 기록했습니다. 이 작업에서는 제어 PC 파일이나 로봇 티칭/카메라 보정을 변경하지 않았습니다. 로봇 이동·시나리오 실행·IO 출력 명령을 보내지 않았습니다.

## 실제 실행 구조

- camera.target_pose는 camera.pose(robot, camera.extrinsic(), coord)를 호출합니다. SDK의 카메라 외부 보정이 이미 적용된 마커 좌표이므로 Python에서 카메라 장착 변환을 한 번 더 곱하지 않습니다.
- main4: WORLD 마커 측정 → 마커×marker_to_left_handle/hinge로 LOCAL 좌표 등록.
- main5: Tool hook 선택 → 손잡이 LOCAL 접근 → grasp1/grasp2 경로.
- 현재 main5의 offset은 (0,0,0)입니다. 기존 검토본의 -2.5mm와 다릅니다.
- **현재 main5는 파지 후 return합니다. 아래 Rotate/Drive 문 열기 코드는 도달하지 않습니다.** 후크 삽입 확인용 정지로 보이며 임의로 return을 제거하지 않았습니다.
- scenario_utils는 SDK EulerZYX 생성자를 사용합니다. 실제 SDK에서 행렬을 직접 추출했습니다. 예를 들어 grasp2의 (180,0,0)은 SDK에서 Z축 180도 행렬이며 Python의 Rx180으로 추측하면 틀립니다.

## 실측 피드백 교차 검증

정지 파지 자세의 J1~J6와 SDK tcp_rbase를 읽어 FR5 GLB FK로 비교했습니다.

- 종전 Python 후크 접촉점(J6 기준): (0,-147.14,148)mm.
- 실제 hook Tool TCP: (-12.6,-141.265,48)mm, GLB J6→SDK 플랜지 100mm를 합친 접촉점은 **(-12.6,-141.265,148)mm**.
- 종전 점은 SDK TCP에서 13.902mm 벗어났습니다.
- 수정 점은 같은 관절값의 SDK TCP와 수치 정밀도 내에서 일치했습니다. 이는 좌표 계산 검증이며 실제 기계 정밀도를 뜻하지 않습니다.
- 현재 SDK TCP는 측정 마커×손잡이 변환×grasp2로 계산한 목표와도 일치했습니다. 실제로 파지 목표 자세에서 정지한 상태를 읽었습니다.

## 후크 우선 배치

현재 마커 작업 좌표와 grasp2 티칭을 이용해 후크 TCP 목표를 구하고, CAD의 왼쪽 손잡이 내부 형상(material 36) 중심이 그 목표에 오도록 CAD X/Y/Z/yaw를 계산합니다. CAD 수직 자세는 유지하며, 마커 X 수평/Y 수직 축 조건을 검사합니다. 실제 로봇 위치·티칭을 바꾸지 않습니다.

이번 측정 기준 계산값:

| 항목 | 값 |
|---|---:|
| X | -0.160333737m |
| Y | 2.077292170m |
| Z | 0.798581140m |
| yaw | 7.300224° |

당시 수동 배치의 손잡이 중심은 목표에서 약 15.714mm 떨어져 있었습니다. 새 배치는 그 계산상 중심 오차를 제거합니다. TCP 점의 일치만으로 후크 전체 형상의 무충돌 삽입이나 이후 롤러 동작을 보장하지 않습니다.

사진/실측 설명으로 배치한 CAD 마커와 실제 티칭 손잡이 관계도 완전히 일치하지 않습니다. 후크 우선 배치에서 CAD 마커 그림과 관측 마커 중심 간 차이는 약 40.7mm입니다. CAD 형상 기준, 표면 깊이, 손잡이 좌표의 정의가 다를 수 있습니다. 기존 30mm/52.5mm 마커 그림을 임의로 바꾸거나 카메라 보정으로 이 차이를 숨기지 않았습니다. 이번 기준은 사용자가 우선순위로 정한 **후크 파지 TCP→CAD 손잡이 내부 중심**입니다.

## 적용

- 사용자 studio_settings.json을 `.bak-hook-teaching-20261109-172020.json`으로 백업하고 후보 배치와 hook_teaching 모드를 저장했습니다.
- 실행 중인 구 프로그램은 종료할 때 이전 메모리 설정을 저장하므로, `pending_hook_alignment.json`에도 검증된 후보를 별도 보관했습니다. 새 프로그램이 다음 시작 시 장착/모델/티칭 해시가 같은지 확인한 뒤 한 번 적용하고 `applied_hook_alignment.json`으로 보관합니다.
- 프로그램을 완전히 종료 후 재시작합니다. 이때 모델 후보가 적용됩니다. 다음 정상 main4 측정 때에도 같은 후크 파지 기준으로 갱신합니다.
- 설정 위치: 설비 배치 → 마커 자동 배치 설정 → **후크 → 왼쪽 손잡이 파지 위치 정렬 켜기 (티칭 기준)**.
- 현재 단계에서는 전체 궤적 자동 배치보다 후크 우선 모드를 사용합니다. 저장된 전체 궤적 배치는 보류했습니다.
- 컨트롤러의 실제 티칭 데이터가 바뀌면 네이티브 SDK 행렬을 다시 추출해야 합니다. 현재 자료는 이번에 읽은 세 파일 버전 기준이며 자동 원격 동기화 기능은 아닙니다.

Python 수동 문 데모의 IK 경로를 임의로 바꾸지 않았으며, 실측 피드백 기반 문 접촉/전체 녹화의 후크 좌표만 실제 TCP로 통일했습니다. Isaac mirror에는 수정된 CAD 위치와 기존 실측 팔 자세가 전달됩니다.
