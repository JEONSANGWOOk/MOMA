# LM2→LM1 전체 녹화로 최초 설비 배치 탐색

Python 프로그램을 재시작한 뒤 **LM2→LM1 연동** 창에서 사용합니다. 이 기능은 실제 로봇 궤적을 측정하고 가상 문 접촉에 맞는 설비 배치를 찾는 기능입니다. 실제 설비를 이동시키거나 로봇 티칭을 변경하지 않습니다. 실제 로봇이 문을 성공적으로 여는 것을 가상 결과만으로 보장하지 않습니다.

## 최초 한 번

1. 실기 지도와 위치 신뢰도, 팔/엔드이펙터/설비 CAD를 확인합니다. 실제 문은 닫힌 상태이며 LM2에서 정지해야 합니다. 기존 이동/팔 인터록은 그대로 적용됩니다.
2. Runtime 로봇 연결 및 최신 6축 관절 수신을 확인합니다.
3. **최초 전체 녹화 + 설비 배치 탐색 · 연동 실행**을 사용자가 누릅니다. 이 버튼은 기존 LM2→LM1 이동과 main2/main3 동작을 실제로 실행합니다. 단순 분석 버튼이 아닙니다.
4. 출발 전부터 main3가 정상 종료할 때까지 약 30Hz로 원본 AMR x/y/theta, 팔 6축(rad), 후크/롤러 지도 좌표, 베큠 IO2~5, 위치 신뢰도 및 새 마커 측정을 기록합니다. 3D 화면이 닫혀도 Tk 프로그램이 실행 중이면 녹화합니다. 수신되지 않은 자세는 보간해 만들지 않고 누락으로 기록합니다.
5. 정상 완료 후 자동으로 탐색 창이 열립니다. 새 마커가 녹화됐으면 마커 기반 직접 배치를 탐색 중심으로 사용하고, 없으면 녹화 시작 당시 CAD 배치를 중심으로 사용합니다. 현재 범위는 XY 반경 25cm, 각도 12도 안이며 Z/roll/pitch는 유지합니다. 전역 탐색이 아닙니다.
6. 최대 약 81개 후보를 비교합니다. 화면과 동일한 SurfaceDoorFollower 및 동일한 CAD 문/후크/롤러 정의를 사용합니다. 계산은 약 10Hz 측정 표본으로 수행하며 원본 전체 녹화는 보존합니다.
7. 결과의 위치·최대/최종 각도를 확인하고, 아래 시간 슬라이더로 후크·롤러·AMR 및 문 각도의 상면 미리보기를 검토합니다.
8. **탐색 결과 적용·저장 → 이후 연동 자동 배치**를 누르면 CAD에 적용하고 저장합니다. 기준 미달이면 저장하지 않습니다. 연결/지도/모델 설정이 변경되거나 연동 진행 중이면 적용하지 않습니다.

가상 통과 조건은 후크 접촉 최소 3회, 롤러 접촉 최소 3회, 롤러가 후크 이후 최소 5도 더 열며 115도 이상 열림, 닫기 접촉 최소 3회 및 마지막 15도 이하입니다. 이는 120도 열기/닫기를 위한 표시 모델의 허용 기준입니다. 물리적 힘·마찰·안전 충돌 검증을 뜻하지 않습니다. 조건 미달일 때 허용 오차를 임의로 늘려 성공으로 처리하지 않습니다.

## 이후

일반 **LM2→LM1 연동 실행**을 누르면 같은 지도/호스트/팔 장착/CAD/엔드이펙터 설정에 저장된 배치를 먼저 자동 적용하고 실행합니다. 전체 자세 녹화는 기본 켜짐입니다. 최신 마커가 첫 녹화에 포함됐다면 학습한 마커↔CAD 관계를 보존해, 다음 main4 마커 작업 좌표에 설비가 맞춰집니다. 마커가 없었다면 고정 MAP 위치만 복원하며 새 마커에 대한 상대 배치 변화는 학습할 수 없습니다.

녹화 경로는 `%USERPROFILE%/.seer_amr_console/door_trajectory_sessions/`입니다. 각 실행은 별도 JSON이며 정상 완료 기록만 `latest.json`을 갱신합니다. 취소/실패/연결 단절 기록도 별도 파일에 남지만 이전 정상 기록은 덮어쓰지 않습니다. 누락 간격 0.5초 초과, 누락 10% 초과, 낮은 위치 신뢰도(<0.6) 포함 시 탐색을 차단합니다. 최대 녹화 시간은 10분입니다.

**이전 전체 녹화로 설비 위치 탐색 (로봇 실행 없음)**은 로컬 JSON만 분석하며 로봇 명령을 보내지 않습니다. 연동 해제는 후속 실행을 차단하는 기존 기능이며 이미 시작한 물리 동작을 정지시키는 버튼은 아닙니다.

저장한 배치는 Python 3D와 연결된 Isaac mirror에 전달됩니다. Isaac의 별도 물리 모드가 실제 힘으로 같은 결과를 낸다는 뜻은 아닙니다. 실제 궤적을 사용하는 최초 현장 검증은 사용자가 정상 작업 중 진행해야 합니다. 개발 과정에서는 실제 이동/시나리오를 실행하지 않았습니다.
