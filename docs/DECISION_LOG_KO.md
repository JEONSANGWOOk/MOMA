# 상황·근거·결론·동작 판단 로그

프로그램을 다시 실행하면 판단 로그를 자동 기록한다. `이벤트 로그` 화면의 `판단` 행에서 확인하고 `판단 로그 폴더` 버튼으로 전체 파일을 연다. 화면의 CSV 내보내기도 판단 행을 포함한다.

저장 위치: `%USERPROFILE%/.seer_amr_console/decision_logs/`

- `decisions.jsonl`: 한 줄에 하나의 구조화된 JSON 판단 기록.
- `decisions.txt`: 같은 기록을 `상황 → 근거 → 결론 → 동작` 문장으로 저장.
- 미션 중 판단은 기존 `mission_reports`의 JSON `decisions` 배열과 TXT 보고서, 수행 보고서 화면에도 포함한다. 판단 행은 작업 성공/실패 횟수에 더하지 않는다.

각 기록에는 시각(밀리초), 실행 세션 ID, 순번, SIM/REAL 구분, 앱 모드(`host_backend`), 미션 시작 시각·루프·단계, 판단 위치(`source`), 현재 상황(`situation`), 관측값과 기준(`evidence`), 결론(`conclusion`), 선택/실행한 동작(`action`)이 있다. 로봇팔 SIM을 REAL 앱에서 시험해도 SIM으로 구분한다.

예시:

```text
상황: BOX 장애물이 주행 경로를 차단
근거: 관측 속도 0.00m/s, 동적 기준 0.08m/s, 정지 관측 기준 2.0초,
      선택 시나리오 wait_reroute, 대기 5.1초 / 기준 5.0초
결론: 설정 대기 시간 경과
동작: 대기 종료 → 연결 경로 재탐색

상황: 실기 장애물 대응 중 취소 요청
근거: 취소 ACK 없음, 제어기 상태 WAITING, 속도 0.00m/s, 확인 제한 15초
결론: 취소/정지 확인 조건 미충족
동작: 재주행 금지 → 최신 상태 대기
```

## 적용한 판단 범위

| 범위 | 기록하는 판단 |
|---|---|
| SIM 장애물 관측 | 추적/미관측, 지도 고정 장애물 여부, 관측 시간·변위·속도로 정적/동적/판단 중 분류 |
| SIM 주행 | 최초 연결 경로, 전체 전방 검사, 동적 충돌 예측, 속도·제동·곡률·영역 제한, 방향 정렬, 충돌 거리와 연속 이동 충돌 |
| 장애물 정책 | 분류별 설정, 대기 시간, 정지 유지, 국소 우회, 원래 경로 복귀, 연결 경로 후보·선택 비용·충돌 검사, 재시도 실패 횟수, 무진행 감시, 자유 공간 복구, 목적지 패스 |
| BLOCKED 회복 | 제한 후진, 후방 공간 부족, 새 장애물로 정지, 복구 통로 부재, 안전 우회 경로 적용 |
| REAL 장애물 대응 | 기능 활성 여부, 관측 블록점의 움직임, 정책·대기 시간, LiDAR 최신성, 취소 ACK 이후 최신 정지 상태, 재주행 ACK/거부/시간 초과, 패스 전 취소 확인 |
| 미션 | 진입 인터록, 실행 중 연결·전원·제어권·비상정지 검증, 완료/대기, 직선 거리·회전각, DI 대기·분기, 지연, 제한 시간·복구, 도달 불가 후속 작업 생략, 반복 종료, 실패/취소 요청 |
| 기존 순환 미션 | SIM 경로 종료, REAL 주행 상태·완료의 최신성/거리 확인, 실패 중단, 반복 판단 |
| 수동 입력 | 수동 이동 안전 검사, 조종 lease 만료, 팔 안전 자세, REAL 조종 안전 조건 소실, 게임패드 AMR/팔 허용 조건·입력 최신성·정지, 포커스 소실 |
| 팔/그리퍼 | 등록 작업·좌표계·관절 한계·IK 실패, 중간 관절 자세 충돌과 예상 충돌, 완료·시간 초과·IO 대기, 파지/해제·파지력·가속도·허용하중, REAL safe_pose 피드백·허용 오차·피드백 지연 |
| 충전 | 저전압·충전소 후보·선택, 도달 가능한 충전소 없음, 충전 확인·상한 도달·재개, REAL 연결/주행 실패·충전 제한 시간 |
| 위치/경로/운영 | 지도·저장 위치 호환성, 자동 위치 확정 신뢰도, 표시용 노드 추정 근거, 방문 경로 시간/거리·제외 노드, 개발 권한, 음성 명령 해석·유효시간·모드·실행 허용 검증 |
| 명령/장치 | 명령 허용·큐 등록, 실제 worker 전송, 제어기 수락/거부, 응답 오류와 자동 재전송 금지, 장치 단계 실패 |

SIM 판단은 GUI 계산 결과이고 REAL의 수락/정지/완료 판단은 수신한 제어기 응답과 상태를 근거로 한다. `요청 등록`, `송신`, `ACK 수락`을 실제 이동 완료와 구분한다. 표시용 가까운 노드 추정은 미션 도착 판단에 사용하지 않는다. REAL 블록점만으로 사람·장애물 종류를 추정하지 않는다.

## 성능과 보관

판단이 바뀌거나 실제 경로 적용·재시도·분기·실패가 발생하면 즉시 기록한다. 같은 판단이 유지되면 5초 간격으로 최신 상황과 직전 동일 판단 반복 횟수를 기록한다. 모든 반복 tick의 좌표를 각각 저장하는 방식은 아니다.

디스크 쓰기는 별도 스레드에서 처리하고 화면에는 tick당 최대 40행씩 반영한다. 종료 시 대기 중 파일 기록을 처리한다. JSONL/TXT 각각 8MiB를 넘으면 분할하며 이전 파일 20개를 유지한다. 더 오래 보관하려면 폴더를 별도로 복사한다. 디스크 저장 오류는 이벤트 로그의 ERROR로 표시한다. 화면/메모리 로그는 기존 제한을 유지하며 전체 기록은 저장 파일에서 확인한다.

## 검증

`python -X utf8 -m unittest discover -s tests`와 `tools/decision_log_smoke.py`, `tools/fr5_smoke.py`, `tools/render_performance_smoke.py`로 검증한다. 실기 통신은 합성 응답으로 시험하며 실제 로봇에 접속하거나 명령을 보내지 않는다.

통합본 테스트 423개 통과. Tk 화면의 판단 행·장애물 우회·미션 보고서·지도 undo용 스냅샷·자동 파일 저장과 FR5 GUI smoke를 확인했다. 로그를 활성화한 1100×700 반복 렌더링 6프레임 중앙값은 20.25ms, AMR·팔 동시 움직임 2초 시험의 world 갱신 callback은 약 14.3회/초였다. 지도·모델·시스템 부하에 따라 달라지는 단일 시험 결과다.

시험 결과: `artifacts/decision_log_smoke.jsonl`, `artifacts/decision_log_smoke.txt`, `artifacts/decision_log_performance.json`. 필요하면 `python -X utf8 tools/decision_log_smoke.py --output-dir artifacts`로 새 예시 로그를 만든다.
