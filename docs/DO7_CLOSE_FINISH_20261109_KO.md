# DO7 3구간 및 닫기 OFF 자동 마무리

이 문서가 기존 DO7_DOOR_OPENING_KO.md의 닫기 정책을 대체합니다. 사용자 요청 변경에 따라 다음 순서입니다.

1. 첫 DO7 ON: 후크 접촉 후 실측 자세로 약 60도 여는 구간. 첫 OFF: 각도 유지.
2. 두 번째 ON: 롤러 접촉 후 추가 열기. 두 번째 OFF: 열린 각도 유지. OFF에서 닫기를 시작하지 않습니다.
3. 세 번째 ON: 롤러 닫기 추종. 이 구간 OFF를 확인하면 실제 기하 추종에서 남은 가상 문 각도를 0도로 부드럽게 마무리합니다.

자동 마무리는 Python/Isaac의 **표시 애니메이션**입니다. 실제 로봇이나 실제 문을 움직이는 명령을 보내지 않습니다. 잔여 각도에 따라 약 0.6~3초 동안 smoothstep으로 닫습니다. IO/관절 수신이 불명확하면 유지하고, 재개 시 한 번에 끝 각도로 점프하지 않습니다. 실행 도중 프로그램을 재시작해 단계 이력을 잃으면 롤러 ON을 임의로 닫기라고 추측하지 않고 후크 단계부터 시작하도록 표시합니다.

## 이번 현상 확인

실행 중인 Viewer의 vacuum_io.outputs에는 아직 2~5만 있고 7이 없었습니다. 새 Python이 문 각도를 유지하던 직접 원인입니다. 설치된 read-only DO7 코드가 실행 프로세스에 반영돼야 합니다. 현재 로봇팔·AMR 모두 대기로 확인되지 않아 Viewer 재시작을 수행하지 않았습니다.

마커 배치는 초기 측정에 변화량 제한을 생략했던 경로를 제거했습니다. hook_teaching/marker_anchor 모두 첫 측정부터 XY 5cm, yaw 5도, Z 5cm를 넘는 변화는 적용하지 않고 상태창에 이유를 표시합니다. 새로운 정확한 절대 배치가 이 한계 밖이면 사용자 검토/재배치가 필요하며 자동으로 설비를 돌리지 않습니다.

마커 브릿지에는 실제 시나리오에서 사용한 SDK WORLD 행렬을 m로 변환한 map_matrix를 추가했습니다. 지원되는 API에서는 이 좌표를 직접 사용해 수신 시점 AMR 위치/방향과 다시 합성하지 않습니다. 과거 API는 RBASE 합성을 사용하되 동일한 급변 제한을 적용합니다. 카메라 측정 자체의 정확도를 보증하지 않습니다.

직전 파지 목표와 SDK TCP로 검증한 CAD 배치를 재시작 적용 대기 파일에 준비했습니다. 실행 중 프로그램 설정은 강제로 바꾸지 않았습니다. 실제 로봇 위치/카메라 보정/시나리오 IO setter는 변경하지 않았습니다.

작업 종료 후 Viewer 재시작 → Runtime 로봇 재연결 → Python 완전 종료·재시작이 필요합니다. 이후 상태 API에 outputs.7과 새 마커의 map_matrix가 수신되는지 확인해야 합니다. 닫기 ON/OFF는 사용자가 scenario.py에 추가하기로 한 신호이며, 이 작업에서 실제 IO를 출력하거나 임의로 실기 시나리오를 실행하지 않습니다.

제어 PC 최신 scenario.py를 재조회하여 main5에 ON/OFF 두 쌍, main12의 Rotate(0,-150,0) 전후에 ON/OFF 한 쌍이 추가된 것을 확인했습니다. 후크 열기는 Rotate(0,60,0)입니다. 해당 실기 명령은 수정하거나 실행하지 않았습니다.


## 직접 SDK 수신 경로

기존 베큠의 실제 사용 경로는 제어기→제어 PC SDK OutputSignal(CNTROB,2/3/4/5)→Runtime API→Python입니다. 직접 FAIRINO SDK 연결 경로도 기존 프로그램에 있으며 GetDO로 읽은 DO 비트와 GetActualTCPNum으로 읽은 Tool 번호를 사용할 수 있습니다. 새 DO7 선택기는 기존 SDK 세션이 연결돼 있고 0.8초 이내의 정상 DO7 값이 있으면 직접 수신을 우선하고, 없으면 Runtime으로 전환합니다. 새 세션을 자동 생성하거나 제어기 상태를 변경하지 않습니다. 직접 연결에서는 Viewer를 재시작할 필요가 없습니다.

현재 사용자 설정은 FAIRINO 직접 드라이버가 아니며 이 PC에 fairino Python 패키지도 없습니다. 그러므로 직접 수신이 현재 활성화됐거나 실제 DO7을 확인했다고 주장하지 않습니다. 직접 경로용 getter/우선순위/기록과 모의 테스트만 완료했습니다. 실제 작업 중 Viewer 재시작 및 새 로봇 제어 세션 생성은 하지 않았습니다.
