# DO7 문 열기 구간 연동

사용자 확인: DO7은 로봇팔 DO7 출력이며 열기에만 사용합니다. 닫기는 기존 롤러 접촉 추종을 유지합니다. Python은 DO7을 읽기만 하며 출력/시나리오/이동 명령을 보내지 않습니다.

## 제어 PC 현재 코드 확인

2026-11-09 scenario.py의 main5에 후크 ON → Rotate/Drive/완료 대기 → OFF → 후크 빼기/자세 변경 → 롤러 ON → Tool/접근 MoveL/Rotate/Drive/완료 대기 → OFF가 들어 있습니다. 파지 직후의 return은 현재 코드에서 제거된 상태입니다. 현재 후크 Rotate는 **60도**이며 사용자가 말씀한 45도와 다릅니다. 실제 회전 명령을 45도로 바꾸지 않았으며 화면 역시 무조건 45도로 강제하지 않습니다.

두 번째 ON은 SetTool(tool_roller)와 접근 MoveL 이전에 있습니다. ON만으로 열리도록 하면 접근 자세 변경까지 문 각도에 반영될 수 있어, Python은 실제 Tool이 롤러로 바뀌고 CAD 접촉이 확인된 다음 자세 각도를 사용합니다.

## 표시 동작

- DO7 ON + hook Tool + 접촉: 후크 열기.
- 첫 OFF: 열림 각도를 고정하고 후크 빼기/롤러 자세 변경 중에는 문을 움직이지 않음.
- 다음 ON + roller Tool + 접촉: 롤러 추가 열기.
- 두 번째 OFF 이후: 기존 롤러 외측 접촉에 따른 닫기만 허용. OFF에서 추가 열림은 금지.
- IO/Tool/관절 수신 불명 또는 오래된 값: 각도 유지. 베큠/다른 Tool로 전환 중에도 DO7을 추측하지 않음.

접촉 확인 후 ON 구간의 실제 J6 지도 회전에서 힌지 수직축 회전량을 추적합니다. DO7만 켜져 있어도 자동으로 45도/120도가 되는 방식이 아닙니다. 좌표는 기존 마커/후크 정렬을 사용합니다. 미세 역회전은 진행 각도를 보류하고 회복 후 이어가므로 작은 위치 흔들림 때문에 전체 개방 추종이 영구 해제되는 문제를 줄였습니다. 가상 표시이며 실제 힘/마찰/접촉 성공을 증명하지 않습니다.

Python의 문 추정 상태줄에 DO7 대기/접촉 대기/후크 당기기/롤러 추가 열기/닫기 추종 상태를 표시합니다. Isaac mirror는 계산된 문 각도를 동일하게 받습니다.

## 상태 읽기와 적용

제어 PC viewer_moma.py의 read_vacuum_io에 `OutputSignal(CNTROB,7)` 두 인수 GET을 추가했습니다. 기존 vacuum_io.outputs의 2/3/4/5를 유지하고 7을 추가합니다. DO7 읽기 실패는 베큠 IO 전체를 무효화하지 않습니다. sample_time 갱신 여부와 실제 tool TCP 위치로 최신 값/Tool 종류를 확인합니다.

패치는 백업 후 설치했습니다. 현재 실행 중인 Viewer는 로봇팔·AMR idling=true로 확인되지 않아 재시작하지 않았습니다. 사용자 작업이 끝나면 Viewer 재시작과 Runtime 재연결, Python 재시작이 필요합니다. 적용 전 기존 API에는 DO7이 없으므로 새 Python은 'DO7/Tool 상태 미수신 · 문 각도 유지'로 표시합니다.

기존 프레임 녹화/전체 연동 녹화에 DO7과 Tool 종류를 추가했습니다. 새 기록의 SIM 재생과 전체 궤적 탐색에도 동일한 DO7 상태 모델을 적용합니다. DO7이 없는 구 기록은 기존 기하 추종을 사용합니다.

사용자가 작성한 scenario.py의 DO7 setter와 회전/이동 명령은 이 작업에서 변경하지 않았습니다. 실제 IO 출력이나 동작 실행도 하지 않았습니다. 제어 PC 백업은 viewer_moma.py.bak-do7-날짜 파일입니다.
