# 마커 작업 좌표계 기반 설비 배치

## 기존 파일 분석 결과

2026-11-09 제어 PC의 최신 scenario.py와 scenario_data.py를 SSH로 읽어 AST로 실제 실행문을 확인했습니다. 주석/삼중 문자열의 미실행 코드는 제외했습니다.

- main2: 카메라 관측 자세 준비.
- main3: main4 → main5 → main10 → main11 → main12.
- main4: `camera.target_pose(moma, exc.COORD.WORLD)`로 마커의 위치와 방향을 측정하고 `SetLocal`로 마커/손잡이/힌지 작업 좌표계를 등록.
- 손잡이 좌표계 = 측정 마커 행렬 × `marker_to_left_handle` 변환.
- 힌지 좌표계 = 측정 마커 행렬 × `marker_to_left_hinge` 변환.
- main5: 손잡이 LOCAL 좌표로 접근한 뒤 힌지 LOCAL 좌표계의 Y축을 중심으로 후크/롤러 작업. 실제 소스에는 후크 Rotate(0,60,0), 롤러 Rotate(0,100,0) 및 AMR 동시 Drive가 있습니다. 두 숫자를 단순 합산해 화면 도어 각도로 사용하지 않습니다.
- main12: 힌지/손잡이 좌표계를 사용해 롤러 닫기 동작. 실제 실행 Rotate(0,-145,0).

따라서 원래 의미는 **이전 값에 대한 오차 누적 보정이 아니라, 측정한 마커 작업 좌표계 안에서 상대 티칭값을 실행**하는 것입니다.

현재 티칭 원본의 상대 변환(mm, SDK EulerZYX)은 다음과 같습니다. Python에서 로봇 동작을 재전송하지 않습니다.

| 변환 | X | Y | Z | 회전 |
|---|---:|---:|---:|---|
| marker_to_left_handle | 64.817 | 8.045 | 2.365 | 0,0,0 |
| marker_to_left_hinge | -235.007 | 8.043 | -34.409 | 0,0,0 |

## Python에서 사용하는 방법 (새 기본 방식)

1. 실제 AMR 지도 위치와 방향, 팔 장착 위치를 확인합니다. 위치 신뢰도가 0.6 미만이면 배치를 보류합니다. 이 수치는 프로그램 표시 기능의 보수적인 적용 기준이며 로봇 제조사의 안전 기준을 뜻하지 않습니다.
2. Python 재시작 후 실기 3D 화면에서 **설비 배치 → 마커 자동 배치 설정 → 마커 기준 설비 배치 켜기 (수동 기준 등록 불필요)**를 선택합니다.
3. 실제 왼쪽 문이 닫힌 정상 작업에서 main4가 새 마커를 측정하면 설비 X/Y/yaw가 자동 결정됩니다. 버튼은 시나리오나 로봇 동작을 실행하지 않습니다.
4. 실제 팔은 Runtime의 실측 관절값으로, AMR은 위치 피드백으로 표시합니다. 계산한 설비 변환은 기존 Isaac mirror로 전달됩니다.
5. 다음 새 마커 측정 전에는 설비를 고정합니다. AMR이 작업 중 움직인다고 설비가 따라 움직이지 않습니다. 같은 capture_id를 반복 적용하지 않습니다.

이번 마커의 지도 좌표 = 지도→AMR × AMR→팔 장착 × 팔 RBASE→마커. CAD 마커 중심은 손잡이 왼쪽 끝에서 왼쪽 30mm, 하단에서 위로 52.5mm입니다. 마커 X축의 수평 방향을 CAD X방향으로 사용하고, 티칭의 힌지 축인 마커 Y가 수직인지 검증합니다. CAD 바닥 높이 Z와 수직 자세는 유지하며 **XY와 yaw만** 직접 맞춥니다. 정확한 높이/축 방향/팔 장착 오차는 현장 측정으로 확인해야 합니다.

최초 수동 배치와 이전 마커 측정값은 새 방식의 계산에 필요하지 않습니다. CAD 마커 위치·축 대응이 잘못되면 정확하게 배치할 수 없으므로 현장 검증은 필요합니다. 축이 수평/수직 조건에 맞지 않거나 오래된 측정, 이동 중, 다른 지도/호스트/CAD/장착 설정, 큰 후속 위치 점프는 적용하지 않습니다. 보정 실패 시 마지막 배치를 유지합니다.

기존 **수동 배치 기준 등록 예약**은 검증된 수동 배치를 기준으로 상대 변화를 추적하는 별도 선택 기능입니다. 이것을 누르면 이전 상대 방식으로 전환됩니다. 새 직접 배치를 사용할 때에는 누르지 않습니다.

## 제어 PC 설치

로컬 `tools/runtime_viewer_patches`의 아래 세 파일을 제어 PC의 임시 폴더로 복사합니다.

- equipment_marker_bridge.py
- install_marker_bridge.py
- 이 안내 문서

로봇 작업이 끝난 상태에서 제어 PC에서 실행:

```bash
python3 /tmp/moma-marker/install_marker_bridge.py /home/sdc/ws_sdc/viewer
```

설치기는 기존 scenario.py의 main4 안에서 WORLD 마커 좌표를 얻은 직후 읽기 전용 좌표 전송을 추가합니다. viewer_moma.py의 robot 상태에 equipment_marker를 추가합니다. 수정 전 구문과 예상 위치를 검사하고 기존 파일을 .bak-marker-날짜로 백업합니다. 기존 버전과 구조가 다르면 중단합니다. Viewer 재시작/시나리오 Load는 설치기가 수행하지 않습니다. 연동 코드는 IO 출력이나 Move 명령을 호출하지 않습니다.

SDK Matrix 곱/역행렬로 WORLD→RBASE 변환하고, xyz의 mm만 m로 환산합니다. API는 `/api/moma_status`의 `robot.equipment_marker`에 valid, capture_id, marker_id=0, frame=rbase_m, matrix(4×4), age_s를 제공합니다. 보정된 CAD는 기존 Isaac mirror 경로를 사용합니다. 별도 Isaac 위치 설정은 필요 없습니다.

## 정확도와 남은 확인

로컬 좌표 합성/검증/설치기/중복 측정 테스트는 통과했습니다. 2026-11-09 제어 PC에 설치하고 Viewer를 재시작했습니다. 실제 SDK와 설치된 브릿지를 사용한 합성 좌표 변환 검사가 통과했고 `/api/equipment_marker` 응답을 확인했습니다. 실제 마커 인식에 의한 보정 결과와 문 동작은 아직 검증하지 않았습니다. 현장에서 팔 장착 변환, 마커 축 대응 및 닫힌 문 상태를 확인해야 합니다. SDK 읽기 실패는 valid=false로 표시하고 배치에 적용하지 않습니다.

설비 위치 오차를 줄이면 접촉 시각화가 개선되지만, 후크·롤러 형상 오차나 문 추종 모델까지 자동 교정하는 것은 아닙니다. 문 열림을 보장하지 않습니다. 직접 배치는 실측 마커 중심 위치와 티칭에서 확인한 X 가로/Y 힌지 축 대응을 사용합니다. 마커 부착 방향이나 CAD 좌표축이 이 조건과 다르면 적용을 중단합니다. 정밀한 축/장착 검증 없이 완전한 6자유도 정합이나 실제 접촉 정확도를 보장하지 않습니다.

## 마커 표시 위치 실측 반영

마커 중심은 정면 비반전 기준 손잡이 왼쪽 모서리에서 왼쪽 30mm, 손잡이 하단에서 위로 52.5mm(손잡이 길이 105mm의 절반)입니다. Python 3D와 Isaac Sim은 동일한 마커 형상을 사용하며, 문 회전 시 함께 움직입니다. 기존 사진 추정의 손잡이 중심 기준 왼쪽 55mm를 대체합니다. 표시는 실측 상대 위치를 반영하지만 실제 제어기의 marker_to_left_handle/hinge 티칭 변환이나 저장된 자동 배치 기준은 변경하지 않습니다.
