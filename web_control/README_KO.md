# MOMA Mission Control · 로컬 웹 관제

## 실행

프로젝트 루트에서 `run_web_windows.bat`를 실행합니다.
브라우저에서 http://127.0.0.1:8765 로 열립니다. 종료는 실행 터미널에서 Ctrl+C입니다.
기존 `run_windows.bat` 데스크톱 프로그램은 유지합니다. 실제 로봇을 조작할 때는 한 프로그램에서만 제어권을 사용하세요.

첫 실행 시 Python 웹 의존성이 없으면 requirements.txt로 설치합니다.
빌드 결과가 없으면 Node.js 22.12 이상으로 npm ci, npm run build를 수행합니다.
이후 웹 실행에는 Node.js가 필요하지 않습니다. 재빌드는 `run_web_windows.bat --build`입니다.

## 데스크톱 앱을 먼저 실행해야 하나요?

아니요. `main.py` 또는 기존 `run_windows.bat`는 실행하지 않아도 됩니다.
`run_web_windows.bat` 하나가 FastAPI 통신 서버를 시작하고 브라우저를 엽니다. 서버 터미널은 켜두세요.
웹을 제공하는 서버 자체는 Python이므로 Python 설치는 필요합니다.
로봇 PC에서 제공하는 RealSense `/video_feed` 영상 서버와 AMR TCP 중계 서비스는 별도로 실행 중이어야 합니다.

## 2D / 3D

- 2D: 별도 Canvas2D 평면 지도입니다. 지도 점군·벽 선·Station·경로·LiDAR와 로봇 위치/방향 아이콘을 표시합니다. 입체 모델·원근·조명·입체 벽은 표시하지 않습니다.
- 3D: 원본 GLB 설비·AMR·로봇팔·엔드이펙터와 실제 관절/문 각도를 표시합니다.
- 2D 조작: 드래그 이동, 휠 확대/축소, Station 클릭 선택. 선택만으로 주행하지 않습니다.
- 2D에서는 3D 프레임 렌더링을 멈추지만 서버의 로봇 수신과 제어는 계속 동작합니다. 3D로 돌아오면 최신 상태를 표시합니다.

## LiDAR 표시

웹의 `LiDAR` 버튼으로 실시간 점군을 켜고 끕니다. 2D/3D 모두 표시합니다.
SIM은 합성 스캔, 실기는 상태 TCP 세션을 재사용해 1009를 조회하며 실패 시 1101로 조회합니다. 상태·IO·LiDAR 조회를 순서대로 처리하고 주행 명령 연결은 분리합니다. 두 센서의 스캔을 합칩니다.
센서 장착 정보와 현재 AMR 위치로 지도 좌표를 계산하고, 공식 WORLD 좌표는 중복 변환하지 않습니다.
기존 데스크톱에 저장한 장착 보정과 호스트/지도별 LiDAR 정합값도 읽습니다.
상단에 SIM/LIVE, 수신 점 수와 오류를 표시하며, 2초 이상 오래된 점군은 숨깁니다.
실기 조회 전용 연결로도 볼 수 있습니다. `지도 받기`로 실제 지도를 받은 뒤 확인하세요.

## 운영 순서

1. `제어권 가져오기`를 누릅니다. 한 브라우저 탭만 운영권을 가지며 20초 임대, 5초 갱신입니다.
2. `연결` 패널에서 SIM / 실기 조회 / 실기 제어와 AMR IP, FR5 Runtime URL을 선택합니다.
3. 실기에서는 `지도 받기`로 1300/4011 지도 조회를 수행합니다. 지도 업로드는 하지 않습니다.
4. FR5는 Runtime HTTP 피드백 또는 공식 SDK로 관절값을 읽습니다. 실제 AMR 이동에는 SDK의 최신 관절값과 기존 `safe_pose` 작업 확인이 필요합니다.
5. 목적지 선택 후 이동합니다. 순차 미션은 방문 목적지 목록으로 구성합니다.
6. DI/DO는 SEER 1013 상태 조회 및 일반 DO 6001로 연결됩니다. 출력은 정지 상태 및 최신 DO 값 수신 시 가능합니다.
7. 문 초기 각도는 0~120°로 각각 저장할 수 있습니다. 문 추종은 실제 관절 위치 기반 기하 추정이며 힘·토크나 실제 개방 센서값이 아닙니다.
8. 카메라는 로봇 PC 엔드이펙터 RealSense 영상 서버의 /video_feed를 기본으로 연속 수신합니다. Runtime 주소에서 자동 유도하며, 기존 camera_stream_url 설정이 있으면 우선합니다. 여러 브라우저는 하나의 upstream MJPEG 연결을 공유하므로 USB 장치를 중복 점유하지 않습니다. 연결 패널에서 RealSense 자동 / 직접 입력 / 끄기를 선택할 수 있습니다. RGB 영상 표시이며 RTSP/WebRTC나 깊이 영상은 포함하지 않습니다.

## 전시

상단 `전시 화면`으로 3D 뷰를 확장합니다. `운영 화면`으로 즉시 복귀할 수 있고 전체 화면 버튼도 제공합니다.
지도 Station 클릭은 선택만 합니다. 실제 이동은 별도 이동 버튼을 눌러야 합니다.
관람 화면과 서버가 분리되어 브라우저 새로고침이 로봇 연결이나 미션을 초기화하지 않습니다.
서버는 시작할 때 항상 SIM이며 실기 자동 연결/재전송/미션 자동 재개를 하지 않습니다.
SIM/LIVE 및 영상 미연결, 오래된 상태를 구분합니다. 카메라 미연결을 실제 영상처럼 꾸미지 않습니다.

## 데스크톱 문 표시 실시간 동기화

같은 Windows 사용자/PC에서 두 프로그램을 실행하면 데스크톱의 문 열기·닫기, 초기 각도, 로봇 추종과 현재 문 각도가 웹에 자동 반영됩니다.
이 기능을 적용하는 첫 실행에는 데스크톱 앱과 웹 서버를 모두 한 번 재시작하세요. 그 뒤에는 새로고침 없이 반영됩니다.
데스크톱은 약 0.15초 간격으로 문 표시 상태를 atomic JSON으로 공유하고 웹은 WebSocket으로 화면을 갱신합니다.
데스크톱 창을 2D나 다른 탭으로 바꿔도 상태 공유는 계속됩니다. 프로그램이 종료되거나 2초 이상 지연되면 마지막 각도를 유지하고 수신 지연을 표시합니다.
웹에서 초기 각도를 직접 적용하면 웹 설정을 사용합니다. 데스크톱에서 문 설정을 다시 바꾸면 자동 동기화를 재개합니다.
웹 미션 패널의 `데스크톱 문 표시로 동기화` 버튼으로도 다시 연결할 수 있습니다.
문 표시 상태만 공유하며, 로봇 연결·제어권·주행 명령은 공유하거나 추가 전송하지 않습니다.

## 기존 자료 활용

서버는 ~/.seer_amr_console/studio_settings.json의 3D 배치/모델/팔 설정을 읽습니다.
설비 위치는 마지막 확정 기록의 origin을 우선 복원하며 SIM/실기에 같은 위치를 사용합니다. 임시 편집 좌표나 SIM 예시 좌표로 바꾸지 않습니다. 재실행 시에도 저장된 확정 기록을 다시 읽습니다.
웹 초기 문각도와 영상 입력은 별도 web_control.json에 저장해 데스크톱 설정을 덮어쓰지 않습니다.
실기 문 추종은 기존 설비 배치 확정의 호스트/지도 이름과 일치할 때만 수행합니다. 배치 보정은 기존 데스크톱에서 수행합니다.
3D는 원본 GLB를 브라우저 GPU에서 직접 렌더링합니다. AMR·FR5·엔드이펙터·설비의 원본 삼각형, 재질, 원본 씬 바깥의 부속 노드도 유지하며 표시용 면 축소를 적용하지 않습니다. 전체 모델은 약 192만 삼각형이므로 최초 로드 시 모델 파일 전송과 GPU 업로드 시간이 필요합니다. 원본에 없는 형상을 새로 생성하지는 않습니다. 문 추정을 위한 충돌 메시와 FK는 렌더링과 별도로 서버에서 처리합니다.

## 개발

- 프런트엔드: React, TypeScript, Three.js, Vite. 외부 CDN 없이 빌드에 포함됩니다.
- 백엔드: FastAPI, WebSocket, 기존 SEER/FAIRINO 어댑터.
- 빌드: web_control에서 npm ci && npm run build.
- 개발 서버: python -m web_control.server, 별도 터미널에서 web_control의 npm run dev.
- 서버 검증: python -m unittest discover -s tests -p test_web_control.py.
- 브라우저 검증: python tools/web_control_browser_smoke.py (테스트 서버 실행 및 Playwright Chromium 설치 필요).

현재 실행 주소는 로컬 PC 전용입니다. LAN으로 개방하려면 별도 사용자 인증/TLS/운영 권한 설계가 필요합니다. 이 버전의 탭 제어권은 사용자 인증을 대신하지 않습니다.
실기 명령·SDK·카메라 입력과 현장 성능은 실제 장비에서 별도 검증이 필요합니다. 소프트웨어 정지는 하드웨어 비상정지를 대체하지 않습니다.

## PC 웹캠 실시간 영상

1. `python -m pip install -r web_control/requirements.txt`로 OpenCV를 설치합니다.
2. 웹 서버를 재시작하고 제어권을 가져온 뒤, 연결 패널에서 **이 PC 웹캠 (USB / 내장)**을 선택합니다.
3. 웹캠 번호 **0**을 선택하고 **영상 입력 저장**을 누릅니다. 다른 카메라는 번호 1~9를 선택합니다.
4. 실시간 카메라 패널과 확대 화면에서 확인합니다. **영상 끄기**를 저장하면 카메라를 해제합니다.

파이썬 서버를 실행하는 PC의 카메라를 사용하며 여러 브라우저가 하나의 캡처를 공유합니다.
기본 요청은 640×480, 최대 15fps입니다. 실제 해상도와 속도는 장치에 따라 다릅니다.
연결 실패 시 Windows 카메라 설정에서 데스크톱 앱 접근을 허용하고 카메라를 사용하는 다른 앱을 종료하세요.

## 설비 3D 모델 위 실시간 LiDAR

3D 화면에서 `LiDAR`를 켜면 민트색 실시간 점군을 설비 모델 위에 겹쳐 표시합니다.
설비의 불투명 표면이나 유리에 가려지지 않도록 점군을 마지막에 그립니다.
점군은 지도 좌표와 기존 센서 높이(0.1965m)를 유지합니다. 설비 표면에 투영하거나 입체 형상을 생성하지 않습니다.
실기 연결 후 `지도 받기`로 해당 지도를 불러오고, 데스크톱에서 확정한 설비 배치와 LiDAR 보정을 사용하세요.
수신이 2초 이상 지연되면 점군을 숨깁니다. SIM에서는 합성 점군이며 상단 상태에 SIM으로 표시합니다.

## 오른쪽 문틀 후크 추종

오른쪽 문은 손잡이가 아닌 CAD 문틀(재질 33)에 후크 끝이 접근하면 접촉 위치를 잡습니다.
후크가 힌지 중심의 원호를 따라 움직이면 오른쪽 문 표시 각도가 추종합니다. 롤러 밀기로는 오른쪽 문을 열지 않습니다.
접촉 이탈이나 관절 수신 지연 시 마지막 문 각도를 유지합니다. 이는 실제 관절 기반 표시용 기하 추정입니다.
웹에서 직접 추종하려면 문 설정의 실제 관절 기반 추종을 켜고 초기 각도를 적용하세요.
데스크톱 동기화 중이면 수정된 데스크톱 프로그램도 재시작하세요.

오른쪽 카메라 영역의 **웹캠 실시간 보기** 버튼으로 PC 웹캠을 켜고 확대 영상을 바로 볼 수 있습니다. 웹캠으로 전환하려면 먼저 제어권을 가져오세요. 이미 웹캠이 켜져 있으면 제어권 없이도 확대할 수 있습니다. 확대창을 닫아도 영상 수신은 유지됩니다.

**카메라 팝업 열기**로 별도 크기 조절 가능한 창에서 현재 영상을 볼 수 있습니다. 확대창의 **팝업 열기**도 같은 기능입니다. 창 모서리를 드래그하면 영상 비율을 유지하며 크기가 조절됩니다. 팝업 차단 시 이 사이트의 팝업을 허용하세요. 팝업은 현재 서버의 카메라를 공유하므로 추가 USB 점유나 제어권 획득 없이 볼 수 있습니다.

## 웹캠과 RealSense 동시 보기

웹캠 사용 중에도 오른쪽 패널의 **END-EFFECTOR REALSENSE**에서 로봇 카메라 영상을 함께 표시합니다.
**RealSense 실시간 팝업** 버튼은 RealSense 전용 창을 엽니다. 웹캠 팝업과 동시에 열고 각각 크기를 조절할 수 있습니다.
RealSense는 로봇 PC Runtime의 `/video_feed`를 공유 수신하며, 웹캠 전환과 별도로 연결을 유지합니다.
기존 **영상 끄기**는 선택된 주 영상만 끄며, RealSense 전용 수신은 서버 종료 시 해제됩니다.
RealSense 영상 서버가 실행 중이고 Runtime URL 또는 기존 camera_stream_url 설정이 올바른지 확인하세요.

## 파이썬 데스크톱 UI 카메라

상단 **RealSense 실시간 보기**와 **웹캠 실시간 보기**에서 각각 영상을 엽니다.
웹캠 번호를 선택해 팝업을 열면 두 영상을 동시에 볼 수 있으며 창 크기 조절, 화면 맞춤, 확대가 가능합니다.
카메라는 영상 표시만 하며 문 열림/닫힘 판단과 각도 덮어쓰기를 수행하지 않습니다.
로컬 웹 서버(8765)가 같은 웹캠을 사용 중이면 해당 스트림을 공유합니다. 그 외에는 웹캠을 직접 엽니다.
다른 앱이 웹캠을 점유 중이면 해당 앱의 캡처를 종료하세요. 데스크톱 UI 변경은 프로그램 재시작 후 적용됩니다.

## 카메라 표시 영역 통합

웹 UI 오른쪽에는 영상 영역 하나만 표시하며 **RealSense / 웹캠** 선택 버튼으로 전환합니다.
선택한 영상은 확대 버튼과 팝업 버튼에서도 동일하게 열립니다. 별도의 RealSense 미리보기와 중복 버튼은 제거했습니다.
RealSense 보기는 웹캠 캡처를 끄지 않습니다. 웹캠이 꺼져 있으면 제어권을 가져온 후 웹캠 버튼으로 켜세요.

## 오른쪽 문: 후크로 문틀 밀기

오른쪽 문은 후크 끝이 문틀에 닿은 위치를 기준으로, 힌지 원호를 따라 움직이는 후크 위치에 맞춰 열림 각도가 증가합니다.
후크를 뒤로 빼거나 접촉이 끊기면 열린 각도를 유지하며 역방향으로 문을 끌어 닫지 않습니다.
이 동작은 데스크톱과 웹의 관절 기반 문 표시 추정에 공통 적용됩니다. 카메라 문 열림 판단은 사용하지 않습니다.

파이썬 웹캠/RealSense 팝업 상단의 **항상 위** 체크를 켜면 다른 창 위에 유지되고, 해제하면 일반 창으로 돌아갑니다. 기본은 꺼짐입니다. 일반 웹 브라우저 팝업에는 OS 항상 위 제어가 지원되지 않습니다.

## 설비 배치 미세조정 (파이썬 UI)

CAD 배치 설정과 LiDAR 설비 배치 창에 **X −/＋, Y −/＋, Yaw −/＋** 버튼을 추가했습니다.
이동 증분 기본값은 **0.001m (1mm)**, 각도 증분은 **0.1°**이며 목록 선택 또는 직접 입력으로 변경합니다.
X/Y는 지도 좌표 기준이며 Z·Roll·Pitch는 유지됩니다.
LiDAR 배치 창에서는 미리보기만 변경되며 **배치 확정**으로 저장합니다.
일반 CAD 설정에서는 누르는 즉시 적용·저장하며 이전 실기 배치 확정은 해제됩니다. 실기 추종에는 LiDAR 배치를 다시 확정하세요.

## 양쪽 문 엔드이펙터 궤적 추종

왼쪽/오른쪽 구분 없이 후크가 CAD 문틀·손잡이(재질 33/36/37)에 닿은 뒤 여는 궤적으로 움직이면 접촉한 문이 힌지 방향에 맞춰 추종합니다.
롤러의 문 표면 밀기도 양쪽 문 모두 지원합니다. 기존 오른쪽 롤러 제한을 해제했습니다.
닫힘 방향 후퇴·접촉 이탈·수신 공백에는 마지막 열림 각도를 유지합니다. 접촉하지 않은 반대 문은 움직이지 않습니다.
데스크톱·웹 모두 실제 관절 기반 표시 추정이며, 실기 설비 배치 확정 및 문 추종 설정이 필요합니다.

## 오른쪽 문: 정지 자세 이후 추종

오른쪽 문은 후크가 문틀/손잡이 근처에서 **0.4초간 5mm 이내**로 머물면 그 정지 위치를 접촉 기준점으로 잡습니다.
정지 확인 전에는 문 각도를 바꾸지 않고, 이후 후크가 여는 원호를 따라 움직일 때 문 각도가 추종합니다.
접촉 이탈이나 수신 공백 후에는 다시 정지 확인이 필요합니다. 사진의 관절각을 인식하는 방식이 아닌 실제 후크 위치 기반입니다.

## 파이썬 3D 원본 모델 색상

설비·AMR·엔드이펙터 GLB의 원본 baseColorFactor 재질 색상을 읽어 부품별로 표시합니다.
GPU 표시와 기본 Canvas 표시 모두 동일한 원본 색상을 사용하며, GLB 정적 로봇 변환에서도 색상을 보존합니다.
유리는 기존 투명 표시를 유지합니다. 모델의 텍스처 사진까지 재현하는 기능은 포함하지 않습니다.

## 후크가 문틀을 통과하는 표시 보정

관절 수신 두 프레임 사이 후크 이동 구간도 문틀 접촉으로 검사합니다.
중간에 문틀을 만나 여는 방향으로 움직였다면 정지 대기보다 접촉을 우선해 문 각도를 추종합니다.
실제 로봇 위치는 변경하지 않습니다. 이 기능은 3D 표시용 접촉 추정이며 실물 로봇 충돌 방지 제어가 아닙니다.

## 후크 궤적 즉시 추종 (현재 동작)

양쪽 문 모두 정지 대기 시간을 없앴습니다. 후크가 문틀·손잡이에 접촉한 뒤 여는 방향으로 움직이면 다음 수신부터 즉시 추종합니다.
프레임 사이에 접촉면을 지나가는 이동도 검사합니다. 접촉 이탈 시 열린 각도를 유지하고, 무관한 공중 이동에는 반응하지 않습니다.
앞서 설명한 오른쪽 문 0.4초 정지 조건은 더 이상 적용하지 않습니다.

## 좌우 문 작업 순서

왼쪽은 후크로 일부 연 뒤 롤러 접촉으로 전환해 이어서 밀 수 있습니다. 전환 시 기존 열림 각도를 유지합니다.
오른쪽은 후크가 문 안쪽(CAD 로컬 +Y)에 들어온 이력을 확인하고 바깥으로 나오는 움직임부터 후크 추종을 시작합니다.
카메라 판단 없이 실제 관절에서 계산한 위치를 사용합니다. 수신 공백이나 접촉 영역 이탈 시 진입 이력을 초기화합니다.
